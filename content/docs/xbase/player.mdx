## 版本支持

| 功能组 | SA | VC | III |
|---|---:|---:|---:|
| 血量、护甲、金钱、通缉 | 支持 | 支持 | 支持 |
| Proof 与可见性状态 | 支持 | 支持 | 支持 |
| 相对移动 | 支持 | 支持 | 支持 |
| 皮肤、服装、Stat | 支持 | 不支持 | 不支持 |
| SA Cheat 标志 | 支持 | 不支持 | 不支持 |
| 保留死亡/被捕物品 | 支持 | 不支持 | 不支持 |
| 随处存档请求 | 支持 | 不支持 | 不支持 |

使用 `FeatureCapability::PlayerBasicState`、`PlayerRuntimeEffects`、`PlayerProofs`、`PlayerMovement`、`PlayerKeepStuff`、`PlayerSaveGame` 等细粒度能力决定 UI 是否可用。VC/III 不支持的操作返回 `false` 或保持无操作，但宿主必须先通过能力查询禁用入口，不能把无操作当作成功；任何版本都不会访问其他版本地址。

## 可用性

```cpp
struct PlayerSnapshot {
    bool valid;
    Vec3 position;
    float health;
    float armour;
    int money;
    int wantedLevel;
    Types::ProofState proofs;
};

bool IsAvailable();
PlayerSnapshot GetSnapshot();
```

`IsAvailable()` 只报告当前玩家对象是否可用。`GetSnapshot()` 在一次领域查询中返回位置和基础状态；`valid == false` 时其余字段保持默认值。XBase 不向宿主暴露 `CPlayerPed*` 或无类型指针。

## 运行状态契约

宿主每帧先把 UI 状态转换为 `RuntimeOptions`，再由启用了 Player 领域的 `Core::Process()` 唯一执行游戏状态写入：

```cpp
XBase::Player::RuntimeOptions options;
options.godMode = menuState.godMode;
options.autoHeal = menuState.autoHeal;
options.hardMode = menuState.hardMode;
options.freezeWantedLevel = menuState.freezeWantedLevel;
options.wantedLevel = menuState.wantedLevel;
options.freeFlyProtection = inputState.freeFlyActive;
XBase::Player::SetRuntimeOptions(options);

XBase::Core::Process();
```

数据流固定为 `MenuState → RuntimeOptions → Player::Process()`。宿主负责热键与方向输入；XBase 负责 proof、可见性、生命、护甲、通缉和死亡位置状态机。

## 模式

以下模式由 Player 状态机每帧维护，并在关闭功能、玩家对象切换或 `Player::Shutdown()` 时按属性恢复快照。未被 XBase 修改的生命、护甲、proof 或可见性不会被无差别回滚。宿主只有在移除旧 Player Process 后，才能启用 `Core::Domain::Player`，否则会产生两个状态写入者。

```cpp
void SetNeverWanted(bool enable);    // 永远不被通缉（SA）
void SetGodMode(bool enable);        // proof 与生命保护
bool IsGodMode();
void SetInvisible(bool enable);      // 隐身模式
bool IsInvisible();
void SetHardMode(bool enable);       // 生命上限 50、护甲归零，关闭时恢复快照
bool IsHardMode();
void SetFreeFly(bool enable);        // 自由移动防护；方向输入仍由宿主提供
bool IsFreeFly();
```
